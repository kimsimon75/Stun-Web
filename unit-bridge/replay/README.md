# 원본 맵 리플레이 분석 / 파일 감시

웹 전송이 포함된 Windows 실행 파일은 `dist/StunReplayLink.exe`입니다. 최신 사용법은 [WEB-LINK.md](../WEB-LINK.md)를 보세요. 아래 내용은 별도 Node 분석 도구 설명입니다.

맵 수정이나 프로세스 메모리 접근 없이 `.w3g` 파일을 읽습니다. 현재 검증한 대상은 `ORDR_S2_2.323[R].w3x`, Reforged의 post-2.0.2 액션 형식입니다. 이전에 만든 StunUnitLink.exe와 별도인 Node 분석 도구입니다. 현재 보유 패 전체를 확정하는 프로그램은 아직 아닙니다.

프로젝트 폴더에서 의존성을 설치한 뒤 실행합니다. Node 20 이상이 필요합니다.

```powershell
npm install
node unit-bridge/replay/cli.cjs "C:/경로/Replay.w3g"
node unit-bridge/replay/cli.cjs --watch "C:/경로/진행중인Replay.w3g"
```

500ms마다 파일 변경을 확인하고 완성된 압축 블록과 게임 기록까지만 분석합니다. 파일 헤더의 블록 수가 아직 갱신되지 않아도 실제로 존재하는 완성 블록을 읽습니다. 끝의 미완성 조각은 다음 갱신을 기다립니다. 완성된 앞부분을 재분석하여 결과 파일을 교체하므로 중복 누적하지 않습니다. 파일을 줄이거나 교체해도 새 내용으로 분석합니다. 입력 크기는 32MB로 제한했습니다.

결과: `dist/replay-analysis/live-observed-history.json`. 일반 채팅·계정명·세이브 내용은 출력하지 않습니다. `commandPlayerId`는 명령을 내린 플레이어이며 소유권을 확정하지 않습니다. `observations`는 선택 관측 이력이고 `commands`는 시도한 명령입니다. 웹이나 Netlify에는 자동 전송하지 않습니다.

## 실제 파일에서 확인한 것

- 선택 액션 0x19: 1,996건, 111종, 종류가 확인된 개체 태그 415개.
- 확장 액션 0x7b: 명령 주체 태그·능력 ID·명령 ID 1,554건. 파서가 기본적으로 생략하는 데이터도 보존했습니다.
- 동기화 메시지: 236건. 이 형식의 raw 0x77은 문자열 prefix/value 동기화인데 w3gjs 4.3.0은 구형 W3API 구조로 읽었습니다. 이를 보정한 결과 프레임 기록도 950건에서 957건으로 늘었습니다.
- 조합 능력 명령 69건, 조합 채팅 명령 2건. 능력 이름과 재료 설명은 2.323 맵의 w3a/wts에서 추출했습니다.
- 선택·그룹·명령주체에 등장한 개체 태그 525개 중 110개는 이번 분석에서 종류를 연결하지 못했습니다.

죠즈 조합 명령은 03:09.997와 03:11.229 두 번이고, 같은 죠즈 개체의 첫 선택은 03:11.738입니다. 상디 전설은 06:57.838 명령 후 06:58.226에 처음 선택됩니다. 이후 09:12~09:14 구간의 상디 조합 명령 네 번에 대응하는 첫 관측 개체는 하나입니다. 따라서 명령 횟수로 생산 수를 세거나 매번 재료를 차감하면 틀릴 수 있습니다. 첫 관측을 곧 생성 시각으로 취급하지도 않습니다.

동기화 236건 중 227건은 시작 직후 CODE_LADD이며, 전체 시간대에 반복되는 보유 패 스냅샷은 발견하지 못했습니다. CODE_LADD는 확보한 인접 버전의 SaveEngine 코드에서 저장 데이터 로드용으로 확인됩니다. 2.323 스크립트 전체는 보호된 항목 때문에 추출하지 못했으므로 해당 버전의 트리거 실행 결과를 전부 복원했다고 주장하지 않습니다.

## 검증 범위

3개 자동 테스트, 실제 파일의 6개 부분 길이 비교, 파일을 30→189개 블록으로 늘리는 감시 테스트를 통과했습니다. 최종 관측 1,996건은 일괄 분석과 일치했습니다. 이는 파일이 늘어날 때 따라 읽는 검증입니다. 분석 시 Warcraft 프로세스가 실행 중이지 않았으므로 실제 게임이 기록을 내보내는 주기와 지연은 아직 측정하지 못했습니다.

현재 패 전체를 확정하려면 아직 이름이 연결되지 않은 참조, 실패·취소된 조합, 랜덤 생성 결과, 사라진 재료를 추가로 해결해야 합니다. 관측 이력은 이미 추출 가능하며, 불확실한 상태를 확정된 패로 표시하지 않습니다.
